账号登录（OAuth 2.0）

用授权码 + PKCE（RFC 6749 / RFC 7636）。玩家在 GoutouStdio 的页面上登录并确认授权，你的游戏只拿到一个授权码，再在服务端换成令牌——密码永远不经过你的服务器。

流程

  1. 生成 PKCE 与 state每次登录都新生成 code_verifier、code_challenge 和随机 state，和玩家会话绑定。
  2. 跳到授权页GET /oauth/authorize。没登录的玩家会先去登录页，登录后回到授权页；已授权过的应用会直接放行。
  3. 拿到授权码玩家点「允许」后，浏览器回到你的 redirect_uri，带 code 和原样返回的 state。
  4. 服务端换令牌POST /oauth/token，带上 code、redirect_uri、code_verifier。
  5. 读取用户信息GET /oauth/userinfo，用返回的 sub 作为你数据库里的玩家主键。

授权端点

GEThttps://goutoustdio.top/oauth/authorize
参数必填说明
response_type是固定 code
client_id是注册应用时拿到的 gs_app_…
redirect_uri是必须与登记值完全一致（含路径、末尾斜杠、大小写）
scope否profile（默认）或 profile email，空格分隔
state强烈建议随机串，回调时原样带回，用来防 CSRF 和串号
code_challenge是43–128 位 base64url：BASE64URL(SHA256(verifier))
code_challenge_method是只支持 S256；plain 会被拒绝
prompt否consent 强制重新显示授权页

参数不合法时直接显示错误页（不会跳转），这是为了防止把玩家送到未登记的回调地址；其他错误按 OAuth 规范带回 redirect_uri。

生成 PKCE

import crypto from 'node:crypto';

const verifier = crypto.randomBytes(32).toString('base64url'); // 43 字符
const challenge = crypto.createHash('sha256').update(verifier).digest('base64url');
// verifier 存服务端会话（或加密 cookie），challenge 放进授权 URL
import base64, hashlib, secrets

verifier = secrets.token_urlsafe(32)
challenge = base64.urlsafe_b64encode(
    hashlib.sha256(verifier.encode()).digest()
).rstrip(b"=").decode()
// 浏览器原生 Crypto；Godot / Unity 也可以调用系统浏览器的这段逻辑
const bytes = crypto.getRandomValues(new Uint8Array(32));
const verifier = base64url(bytes);
const digest = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(verifier));
const challenge = base64url(new Uint8Array(digest));

function base64url(bytes) {
  return btoa(String.fromCharCode(...bytes)).replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');
}

回调与 state 校验

玩家同意后：

https://game.example/oauth/callback?code=67qKeA2lyou8…&state=4f2a…

拒绝授权或参数问题时：

https://game.example/oauth/callback?error=access_denied&state=4f2a…
  • 先比对 state 与会话里的值，不一致直接丢弃（防止攻击者把自己的授权码塞给别的玩家）。
  • 授权码 10 分钟有效、只能用一次；失败请让玩家重新走一遍授权，不要复用。
  • 回调地址只做一次 302 到游戏内页面，不要在浏览器里换令牌。

换取令牌

POSThttps://goutoustdio.top/oauth/token

Content-Type: application/x-www-form-urlencoded。机密客户端用 Authorization: Basic base64(client_id:client_secret)，公共客户端在表单里放 client_id。

参数说明
grant_typeauthorization_code
code回调里的授权码
redirect_uri与授权时完全一致
code_verifier当初生成的 verifier（43–128 位）
client_id公共客户端必填；机密客户端可放 Basic 头
client_secret仅机密客户端，推荐用 Basic 头，避免出现在日志里
 
curl -X POST https://goutoustdio.top/oauth/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d grant_type=authorization_code \
  -d code=$CODE \
  -d redirect_uri=https://game.example/oauth/callback \
  -d client_id=$GS_CLIENT_ID \
  -d code_verifier=$VERIFIER
const body = new URLSearchParams({
  grant_type: 'authorization_code',
  code,
  redirect_uri: REDIRECT_URI,
  client_id: process.env.GS_CLIENT_ID,
  code_verifier: verifier,
});
const r = await fetch('https://goutoustdio.top/oauth/token', {
  method: 'POST',
  headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
  body,
});
if (!r.ok) throw new Error('token 换取失败：' + (await r.json()).error);
const { access_token, refresh_token, expires_in } = await r.json();

响应（字段含义见 令牌与用户信息）：

{
  "access_token": "gs_at_…",
  "token_type": "Bearer",
  "expires_in": 7200,
  "refresh_token": "gs_rt_…",
  "scope": "profile email"
}

公共客户端与机密客户端

类型适用凭据
公共客户端游戏本体、网页游戏、桌面 / 手机 App只有 client_id，必须 PKCE
机密客户端有后端的游戏服务器client_id + client_secret（--secret 创建）
!不要把 client_secret、access_token 打进游戏安装包或前端 JS。玩家能拆包看到的一切都不算秘密。

授权错误

error原因怎么处理
access_denied玩家点了取消回到登录页，提示「需要授权才能登录」
invalid_request缺参数、PKCE 不合法检查 code_challenge 长度与方法
invalid_scope请求了应用未登记的 scope用注册时的 scope，或重新注册应用
unsupported_response_type不是 code固定用授权码模式
✓本地调试想跳过「已授权直接放行」：授权 URL 加 &prompt=consent，每次都会显示授权页。
