回调与验签

付款、退款都会以 HTTPS POST 推到你在 SpacePay 商户后台配置的地址。验签通过、金额与订单核对无误后再发货，重复投递要幂等。

配置

  1. 填地址商户后台 →「Webhook」→ 填 https://game.example/webhooks/spacepay，必须是公网 HTTPS，不能是本机或内网。
  2. 保存签名密钥同页查看 whsec_…，放到服务端环境变量 SPACEPAY_WEBHOOK_SECRET。可随时重置。
  3. 本地联调用内网穿透拿一个临时 HTTPS 地址填进去；投递失败可在后台「重投」。

事件

事件触发游戏侧动作
payment.succeeded玩家付款成功按 reference 找到订单，核对金额与 sku，发货并标记已支付
payment.refunded商户或运营退款扣回已发道具 / 余额，记录退款单

请求头

请求头说明
X-SpacePay-Event事件类型，如 payment.succeeded
X-SpacePay-Delivery事件 ID，重试不变，用它去重
X-SpacePay-Signaturet=时间戳,v1=签名
User-AgentSpacePay-Webhooks/1.0

验证签名

签名 = HMAC-SHA256(webhook_secret, 时间戳 + "." + 原始请求体)，小写十六进制。必须用原始字节计算，不能解析 JSON 再重新序列化。

import crypto from 'node:crypto';

export function verifySpacePay(rawBody, header, secret, toleranceSec = 300) {
  const parts = Object.fromEntries(header.split(',').map((p) => p.split('=')));
  const t = Number(parts.t);
  if (!Number.isFinite(t) || Math.abs(Date.now() / 1000 - t) > toleranceSec) return false;
  const expected = crypto.createHmac('sha256', secret)
    .update(`${parts.t}.`).update(rawBody).digest('hex');
  const a = Buffer.from(expected), b = Buffer.from(parts.v1 || '');
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}
import hashlib, hmac, time

def verify_spacepay(raw_body: bytes, header: str, secret: str, tolerance=300) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(","))
    if abs(time.time() - int(parts["t"])) > tolerance:
        return False
    expected = hmac.new(
        secret.encode(), f"{parts['t']}.".encode() + raw_body, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(expected, parts.get("v1", ""))
// express.json 会丢掉原始字节，用 verify 钩子留一份
app.use(express.json({
  verify: (req, _res, buf) => { req.rawBody = buf; },
}));

  const ok = verifySpacePay(req.rawBody, req.get('X-SpacePay-Signature'), process.env.SPACEPAY_WEBHOOK_SECRET);
  if (!ok) return res.status(400).send('bad signature');
  // ...
  res.json({ ok: true });
});
✓校验时间戳（默认 5 分钟）比只验签名更重要：它挡住重放攻击。签名对但时间戳太旧，直接丢弃。

发货

验签通过后按顺序做：

  1. 去重用 X-SpacePay-Delivery 或事件 id 建唯一索引；重复事件直接返回 200。
  2. 找订单用 data.reference 查你库里的充值订单，不要用金额反查。
  3. 核对金额、币种、metadata.gs_user_id、metadata.sku 与下单时一致。
  4. 发货 + 标记在同一个事务里给 gs_user_id 加余额 / 发道具，并把支付单标成已处理。
  5. 返回 2xx10 秒内响应；返回非 2xx 或超时会重试。
app.post('/webhooks/spacepay', (req, res) => {
  if (!verifySpacePay(req.rawBody, req.get('X-SpacePay-Signature'), SECRET)) {
    return res.status(400).json({ error: 'bad signature' });
  }
  const evt = req.body;
  if (seen.has(evt.id)) return res.json({ ok: true });   // 幂等
  seen.add(evt.id);

  if (evt.type === 'payment.succeeded') {
    const order = db.orders.get(evt.data.reference);
    if (!order) return res.status(409).json({ error: 'unknown order' });
    if (order.status !== 'pending') return res.json({ ok: true }); // 已处理
    if (evt.data.amount_cents !== order.amountCents) return res.status(400).json({ error: 'amount mismatch' });

    db.tx(() => {
      credit(order.gsUserId, order.sku);
      order.status = 'paid';
    });
  }
  res.json({ ok: true });
});

重试与去重

  • 失败后按 1 分钟、5 分钟、30 分钟、2 小时、6 小时 重试，共 6 次；后台可手动重投。
  • X-SpacePay-Delivery 在所有重试中保持不变，是官方去重键。
  • 重复投递是常态，不是异常：发货逻辑必须幂等（唯一索引 / 状态机）。

本地联调

  • 没有公网地址时，先用 SpacePay 的「重投」功能对着内网穿透地址测试。
  • 自己造签名验证：printf '%s.%s' "$TS" "$BODY" | openssl dgst -sha256 -hmac "$SECRET"。
  • Webhook 没到不代表没付钱：先用查询接口按 reference 兜底，再等回调。
