错误码与限流

账号接口用 OAuth 标准错误体（error + error_description），支付接口用 ok + code + request_id。两类都不要把原始报错直接弹给玩家。

OAuth 错误

{ "error": "invalid_grant", "error_description": "授权码无效或已过期" }
HTTPerror常见原因
400invalid_request缺参数、PKCE 不是 S256、code_verifier 格式不对
400invalid_grant授权码过期 / 用过 / redirect_uri 不一致 / verifier 对不上 / refresh 已轮换
400unsupported_grant_type只支持 authorization_code 和 refresh_token
400invalid_scope请求了应用未登记的 scope
401invalid_clientclient_id 不存在、应用停用、机密客户端 secret 错误
401invalid_tokenuserinfo 的 access token 过期、撤销或账号被封禁
429slow_down令牌端点限流，退避后重试

支付错误

{
  "ok": false,
  "error": "金额不是合法十进制数",
  "code": "AMOUNT_INVALID",
  "request_id": "req_9f8e7d6c5b4a3210"
}

报障时带上 request_id，服务端日志能定位到具体请求。

HTTPcode处理
401INVALID_API_KEY密钥缺失 / 错误 / 已吊销，检查环境变量
403MERCHANT_INACTIVE商户未过审或被暂停，去商户后台看状态
400AMOUNT_INVALID / AMOUNT_PRECISION / AMOUNT_ZERO金额必须是两位小数的正数字符串
400AMOUNT_TOO_LARGE超过 $10,000,000.00
400METADATA_TOO_LARGEmetadata 序列化后超过 2KB
409REFERENCE_CONFLICT同一 reference 金额不同，换订单号或金额
409PAYMENT_NOT_PAYABLE / PAYMENT_EXPIRED订单已付、已取消或超 30 分钟，重新创建
400REFUND_EXCEEDS_REMAINING退款超过可退金额，details.refundable_cents 是上限
422IDEMPOTENCY_KEY_REUSED同键不同参数；换键或修正参数
409IDEMPOTENCY_IN_PROGRESS同键请求还在处理，稍等后重试
429RATE_LIMITED每个 API Key 每分钟 120 次，退避重试

限流

接口限额
/oauth/token、/oauth/revoke每 IP 15 分钟 120 次
/oauth/authorize跟随站点页面限流；正常玩家不会碰到
SpacePay /api/v1/*每个 API Key 每分钟 120 次（部署方可调）

超限返回 429，带 Retry-After（支付接口）。用指数退避，别把重试堆在同一秒。

接入排查

  • 授权页 400「回调地址不匹配」：授权 URL 里的 redirect_uri 和登记值有一个字符不同，包括末尾斜杠和 http/https。
  • 换令牌 invalid_grant：先确认 code 没用过且没过 10 分钟，再确认 verifier 与 challenge 是一对。
  • 回调收不到：地址必须是公网 HTTPS，且 10 秒内返回 2xx；看商户后台的投递记录。
  • 验签总失败：九成是用了 JSON 重新序列化后的字符串，改为原始请求体字节。
  • 玩家说付了但没到账：先按 reference 查支付单状态，再查 Webhook 投递记录，最后核对 metadata.gs_user_id。
  • 重复发货：没有按 X-SpacePay-Delivery 或订单状态做幂等。
