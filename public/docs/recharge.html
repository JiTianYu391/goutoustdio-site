创建充值订单

充值直接走 SpacePay 商户 API：你的服务器创建支付单，玩家在收款页付款，SpacePay 用 Webhook 通知你发货。商品名称、金额和 sku 都由你的游戏决定，平台不预设商品；没传商品名时兜底成「100 钻石」。

i完整的 SpacePay 接口（结账页、二维码、结算、对账）在 pay.goutoustdio.top/docs。本页只讲游戏接入要用的部分。

准备

  1. 入驻商户登录 SpacePay，在「我的 → 商户后台」提交入驻，等运营审核通过。
  2. 创建 API Key审核通过后在「API 密钥」创建 sp_live_…。密钥只显示一次，放在服务端环境变量。
  3. 配置 Webhook在「Webhook」填游戏服务器的 HTTPS 地址，保存签名密钥（whsec_…）。

基础信息

项目值
接口地址https://pay.goutoustdio.top/api/v1
鉴权Authorization: Bearer sp_live_… 或 X-API-Key
数据格式application/json; charset=utf-8
金额入参是十进制字符串（"5.00"），响应同时给 amount_cents（整数分）
币种目前只有 USD
时间毫秒时间戳
订单有效期创建后 30 分钟，过期需重新创建

创建支付

POST/api/v1/payments
参数必填说明
amount是十进制字符串，两位小数，如 "5.00"；上限 $10,000,000.00
currency否默认 USD
reference否你的业务订单号（≤80 字符）。同一商户内相同 reference + 相同金额返回同一笔支付，是业务幂等键
description否商品名（≤200 字符），显示在收款页。由客户端商品配置传入；缺省兜底为「100 钻石」
customer_email否付款人邮箱，可用于对账
success_url否付款成功后跳回的地址，必须是你的游戏域名
cancel_url否玩家取消后跳回的地址
metadata否自定义对象，序列化后 ≤2KB，回调原样带回。至少放 gs_user_id 和 sku

请求头带 Idempotency-Key（UUID v4）：超时重试时不会重复扣款，24 小时内同键同参数直接重放原响应。

curl https://pay.goutoustdio.top/api/v1/payments \
  -H "Authorization: Bearer $SPACEPAY_KEY" \
  -H "Idempotency-Key: 8f1c2e3a-6b7d-4c9e-9a21-3d5f7b9c1e42" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": "5.00",
    "description": "月卡",
    "reference": "order-2026-0001",
    "success_url": "https://game.example/recharge/done",
    "metadata": { "gs_user_id": "10001", "gs_username": "alice", "sku": "monthly_pass" }
  }'
// product 来自客户端商品配置，服务端校验后原样传给 SpacePay
async function createRecharge(player, product, orderId) {
  const r = await fetch(`${process.env.SPACEPAY_BASE}/api/v1/payments`, {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${process.env.SPACEPAY_KEY}`,
      'Content-Type': 'application/json',
      'Idempotency-Key': crypto.randomUUID(),
    },
    body: JSON.stringify({
      amount: product.price,                    // 来自游戏商品配置
      description: product.name || '100 钻石',  // 兜底
      reference: orderId,
      metadata: {
        gs_user_id: player.sub,
        gs_username: player.username,
        sku: product.sku || '100_diamonds',
      },
    }),
  });
  const { ok, payment, error } = await r.json();
  if (!ok) throw new Error(error);
  return payment; // payment.checkout_url / payment.qr.svg_url
}
import os, requests

def create_recharge(player, product, order_id):
    resp = requests.post(
        f"{os.environ['SPACEPAY_BASE']}/api/v1/payments",
        headers={
            "Authorization": f"Bearer {os.environ['SPACEPAY_KEY']}",
            "Idempotency-Key": str(uuid.uuid4()),
        },
        json={
            "amount": product["price"],              # 游戏商品配置
            "description": product.get("name") or "100 钻石",
            "reference": order_id,
            "metadata": {"gs_user_id": player["sub"], "sku": product.get("sku", "100_diamonds")},
        },
        timeout=15,
    )
    data = resp.json()
    if not data.get("ok"):
        raise RuntimeError(data.get("error"))
    return data["payment"]

付款页与二维码

成熟收银台（Stripe Checkout、支付宝当面付、微信扫码付）都遵循同一套结构：金额最大、商品与订单号清楚、二维码居中、明确告诉玩家「用手机扫」、状态自动刷新、失败/过期有明确出口。照着这个做就够了。

付款页要素

商户名 + 商品名、大写金额、订单号、二维码（白底留边）、剩余时间、当前设备打开按钮、成功 / 过期状态。

二维码

用 qr.svg_url 直接当 <img src>，或拿 qr.payload 自己生成；内容就是收款页链接，任何相机都能扫。

状态

页面每 3 秒查一次你的服务端；服务端用支付单查询接口对账，Webhook 仍是最终依据。

取二维码

GET https://pay.goutoustdio.top/api/checkout/:token            收款页信息（公开，无需登录）
GET https://pay.goutoustdio.top/api/checkout/:token/qr.svg     二维码 SVG，可直接当图片
GET https://pay.goutoustdio.top/api/checkout/:token/qr         二维码 JSON（payload / svg / 过期时间）

轮询与对账

  • 页面只查你自己的服务端，不要在前端拿着 sp_live_… 去查 SpacePay。
  • 服务端按支付单 ID 查 GET /api/v1/payments/pay_{id}，发现 SUCCEEDED 就补发货——这是 Webhook 丢失时的兜底。
  • 轮询间隔 3–5 秒即可；成功 / 过期后停掉定时器，别一直打接口。
  • 最终一致性以 Webhook 为准，轮询只是让玩家不用等刷新。

设计参考：Stripe 支付页面最佳实践 · 支付宝付款码 / 当面付 · 微信支付扫码交互规范

商品配置由客户端传

卖什么、叫什么、多少钱、发多少，都由你的游戏决定，下单时一起传给服务端；平台不预设商品。客户端什么都没传时兜底成「100 钻石」。

  1. 客户端选商品游戏里维护商品配置，点击充值时把 { sku, name, price, credits } POST 给游戏服务器。
  2. 服务端校验价格是两位小数的正数、名称长度、发货数量上限；不合格直接拒绝。是否只认白名单由你决定。
  3. 服务端下单把校验后的 name 作 description、price 作 amount、sku 放进 metadata 调 SpacePay。
// 游戏客户端：商品配置就在这里，想改随时改
const PRODUCTS = [
  { sku: 'monthly_pass', name: '月卡', price: '5.00', credits: 300 },
  { sku: 'starter_pack', name: '新手礼包', price: '9.90', credits: 600 },
];

const r = await fetch('/api/recharge', {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ product: PRODUCTS[0] }),
});
const { checkout_url } = await r.json();
location.href = checkout_url;
// 游戏服务器：只做格式校验和兜底，价格按客户端传的收
function acceptProduct(input = {}) {
  const sku = String(input.sku || '').trim().slice(0, 40) || '100_diamonds';
  const name = String(input.name || '100 钻石').trim().slice(0, 200);
  const price = String(input.price || '1.00').trim();
  if (!/^\d{1,7}(\.\d{1,2})?$/.test(price) || Number(price) <= 0) return null;
  const credits = Math.min(Math.max(Number(input.credits) || 100, 1), 1_000_000);
  return { sku, name, price, credits };
}

// 可选：有排行榜 / 多人经济时改成白名单，只认服务端登记的商品
const WHITELIST = { monthly_pass: '5.00', starter_pack: '9.90' };
function acceptWhitelisted(input = {}) {
  const p = WHITELIST[input.sku];
  return p ? { sku: input.sku, name: input.name || input.sku, price: p } : null;
}

i发货数量 credits 建议以服务端订单里存的那份为准。Webhook 回来时按订单发货，不要相信再次传来的数字。

幂等与重试

  • 创建支付：带 Idempotency-Key，超时 / 5xx 用同一个键重试；4xx 不要重试。
  • reference 用你的订单号：同一商户内相同 reference 且金额一致会返回同一笔支付，天然防重复下单。
  • 同键不同参数返回 422 IDEMPOTENCY_KEY_REUSED；同键请求仍在处理返回 409 IDEMPOTENCY_IN_PROGRESS。

查询订单

GET/api/v1/payments/pay_{id}

支付成功后状态为 SUCCEEDED，其它状态：CREATED、EXPIRED、CANCELED、PARTIALLY_REFUNDED、REFUNDED。

curl https://pay.goutoustdio.top/api/v1/payments/pay_12 \
  -H "Authorization: Bearer $SPACEPAY_KEY"

玩家从收款页返回但 Webhook 还没到，可先按 reference 主动查一次；最终仍以 Webhook 为准。

退款

POST/api/v1/payments/pay_{id}/refund

不传 amount 退剩余全部，传了就按金额部分退款。退款成功后 SpacePay 推 payment.refunded，游戏侧应扣回已发的道具或余额。

钱去哪了

默认 auto 结算：玩家付的钱实时进入商户所有者账户，可再提现；manual 模式先进可结算余额，由运营审核后结转。两种模式都不影响你按订单发货。

安全清单

  • sp_live_… 只放服务端环境变量，不进前端、不进安装包、不进 Git。
  • Webhook 必须验签，校验时间戳在 5 分钟内，按 X-SpacePay-Delivery 去重。
  • 发货以服务端订单状态为准：metadata.reference 对应你库里的订单，金额与商品也要核对。
  • 怀疑密钥泄露：在商户后台吊销并重新创建。
